# MPU6050 Console Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Print MPU6050 measurements from an ESP32-C3 SuperMini console.

**Architecture:** A single application source initializes NVS and legacy ESP-IDF I2C master, validates/wakes MPU6050 address 0x68, then polls its 14-byte measurement register block every 500 ms.

**Tech Stack:** ESP-IDF, driver/i2c.h, FreeRTOS, Python unittest.

## Global Constraints

- SDA is GPIO4; SCL is GPIO5.
- I2C address is 0x68 because AD0 is wired to GND.
- Sensor power is 3.3V.
- Output includes acceleration, gyro, and temperature every 500 ms.
- The SoftAP/HTTP server is removed.

### Task 1: Write a failing source contract test

Modify tests/test_mpu6050_source.py to require source constants for GPIO4, GPIO5, 0x68, WHO_AM_I validation, PWR_MGMT_1 wake-up, and a 500 ms delay. Run python3 -m unittest tests/test_mpu6050_source.py -v and observe failure because the source does not exist.

### Task 2: Implement console polling

Create main/mpu6050_console.c using driver/i2c.h. Configure I2C_NUM_0 at 400 kHz, wake the MPU6050, read 14 bytes from 0x3B, and log scaled acceleration, gyro, and temperature. Update main/CMakeLists.txt to build it with driver and nvs_flash; delete main/portal.c. Run the source contract test green.

### Task 3: Document wiring

Replace README with the five-wire table, warnings not to use 5V or GPIO8, and build/flash/monitor instructions. Run all source tests and idf.py build if available.
